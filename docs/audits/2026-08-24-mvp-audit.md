# MVP product and code audit — 24 August 2026

## Scope

Combined UX, responsive, accessibility-risk and code review of:

1. free vehicle-check acquisition;
2. unsupported registration outcome;
3. Vehicle Passport overview;
4. component evidence dialog;
5. portable Passport export;
6. mobile acquisition and Passport layouts.

Visual evidence is stored in the task audit artifact folder `vehicle-intelligence-audit`.

## Corrected during the audit

- **Misleading lookup state:** an unsupported but valid registration remained beside the FG11 YKC fixture preview. It now replaces the fixture with an explicit “no vehicle result shown” boundary and official-service links.
- **Dialogs could not close:** required inputs blocked the × and Cancel buttons in component and timeline dialogs. Cancel controls now bypass form validation and were retested in the browser.
- **Owner evidence injection risk:** physically entered component values were inserted into HTML without output encoding. All owner component values are now encoded before rendering, with a regression test.
- **Fragile export interaction:** export attempted an invisible immediate download. It now opens a clear disclosure dialog and requires an explicit “Download Passport JSON” action.
- **Malformed saved records:** valid JSON containing incomplete events could crash timeline rendering. Saved observations, events and component evidence are now filtered against minimum render-safe schemas.
- **Accidental deletion:** diagnostic results and owner timeline entries previously cleared immediately. Both destructive actions now require confirmation.
- **Dead navigation:** the header linked to a hidden account section that did not open. The dead link was removed.

## Confirmed strengths

- Registration is the clear first action and requires no account.
- UNKNOWN and INFERRED states are visible and consistently explained.
- The Passport separates candidate configuration from observed installed components.
- Form controls have visible labels, dialogs have named close controls and status feedback uses live regions.
- Desktop and 390 px mobile layouts showed no horizontal page overflow.
- Official GOV.UK routes remain visible and free.
- The export dialog warns that registration and VIN are present before download.

## Remaining limits and production risks

- The in-app audit browser displayed the export link and produced no console error, but its download-event interface did not report blob downloads; verify the saved filename once in a normal release browser before deployment.
- Keyboard traversal, screen-reader announcements, zoom at 200–400% and measured colour contrast need dedicated assistive-technology testing before claiming WCAG conformance.
- Canonical URLs and sitemap still use `vehicleintelligence.example` until a production domain is chosen.
- Live vehicle data, authentication, cloud persistence and payments remain intentionally disconnected.
- Google Fonts are loaded from a third party; self-hosting should be considered for production privacy and resilience.

- Production dependency audit reports zero vulnerabilities.
- Desktop and 390 × 844 responsive routes were exercised in the in-app browser.
